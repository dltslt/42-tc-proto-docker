## Decisions beyond the brief
- **The middleware, not a catch-all route, owns unknown paths.** A catch-all route did not catch a wrong method on a real path: Nitro's router picked the real path and fell through to the page renderer, so `POST /api/v1/health` returned the HTML welcome page with a 200. The middleware checks every `/api/v1` request against the registry instead. Side effect: a route file without a contract is unreachable, so every route must have a contract.
- **Routes return only what their contract says.** `defineRoute` parses the handler's result with the response schema. This strips extra fields and turns a mismatch into a 500.
- **Wrong method gives 405 with an `Allow` header.** The brief first listed only 400, 401, 403, 404 and 409; 405 was added at review, because it tells a client the path exists. Unknown paths stay 404.

## Task 2 decisions
- **One migration history, not one per layer.** The brief first said each layer's migrations live in the layer. drizzle-kit takes one config and one output folder, and a per-layer split would need an ordered runner and a separate snapshot per layer, with foreign keys across them. The brief now says each layer's *schema* lives in the layer. Adding a layer still touches no existing file: it adds a schema file and a new migration. The cost is that removing a layer needs a migration that drops its tables.
- **The database enforces the item rules.** The foreign key `(space_id, column_id, state)` onto `columns` makes "column in the same space" and "column and state agree" one Postgres rule. The same idea applies to `(space_id, parent_id)`.
- **Events are append-only in the database,** through a trigger (migration `0001`), not only by convention.
- **`COLLATE "C"` on order keys.** The database default is `en_US.utf8`, which sorts `Zz` after `a0`. Fractional keys need byte order, and a test proves it.
- **Postgres code for a `RESTRICT` refusal is `23503`,** the same as a bad reference. I first assumed `23001`; the tests showed otherwise. Task 4 must use the constraint name to tell "bad reference" (400/422) from "still in use" (409).
- **Idle connections:** the pool needs an `error` listener, or a dropped idle connection exits the process.
- **Schema and seed files use relative imports.** drizzle-kit and tsx run outside Nuxt and do not know the `#layers` alias.

## Task 3 decisions
- **The caller is identified before the input is validated.** The brief's diagram had validation first. An anonymous caller now gets 401 whatever they send, and learns nothing about the validation rules. The brief's diagram is updated.
- **`GET /actors` is open.** A client has to see who it can act as before it can send `X-Actor-Id`. It lists every actor, which is fine while the header is not security; real auth replaces it.
- **Secure by default:** a contract needs an actor unless it says `auth: 'none'`. The OpenAPI document declares the header as a security scheme and lists 401 on every route that needs it.
- **404 for an unknown space or item, 403 for one that exists but belongs to another space.** This tells a caller that an id exists. The brief asks for 403; the trade-off is noted.
- **`space_id` is required on `GET /items`.** One space per request keeps isolation simple. Listing across all of an actor's spaces can be added later without breaking anything.
- **Cursor timestamps travel as Postgres text.** A JavaScript Date keeps milliseconds and Postgres keeps microseconds, so two rows could swap places across a page boundary. A test inserts rows microseconds apart; making the cursor round to milliseconds (checked by hand) makes it fail.
- **Cursors are tied to their sort.** A cursor from `position` is refused under `-created_at` with a 400.
- **Read tests use the demo database, read-only.** `tests/global-setup.ts` migrates and seeds it first (a no-op if done). Task 4's write tests will need their own server and database: a test that really commits cannot share `proto_run_102`.
- **Added to the index route:** each layer's list of `actions`. Additive, so the contract is unchanged.
- **Unused `can()` argument names** (`_actor`, `_resource`) are deliberate: the signature is what routes call today, and rules fill in the body later.

## Task 4 decisions
- **HTTP tests run against their own server and database.** `tests/server-app/nitro.config.ts` builds an API-only Nitro server from the same `layers/*/server` folders (no Vue), and `tests/global-setup.ts` starts it on port 3902 against a fresh `proto_run_102_http` database, seeded with the demo data, then drops everything afterwards. The dev database is never touched by tests. Tests that really write cannot leave junk, which matters because events cannot be deleted.
- **Why not the Nuxt build:** a separate production `nuxt build` took 1.5 to 3.5 minutes, nearly all of it in Nitro, even with dependency tracing, minifying and source maps off and the output on the container's own disk. The API-only build takes about 20 seconds, and is skipped when no source file is newer than the last build.
- **`nitropack` is a dev dependency,** pinned to the version Nuxt already uses (2.13.5), because pnpm does not let the project import a package that only Nuxt depends on.
- **Not tested by this server:** the Vue page. It is checked in a browser instead. The write routes were also exercised once by hand on the real Nuxt dev server (create, edit, stale edit, state change, cycle, delete, wrong method), and every status matched the test server's. The demo database was rebuilt from the seed afterwards, since events cannot be deleted.
- **Move names a neighbour (`after_id` / `before_id`), not an order key.** The brief said `position`. Clients would otherwise need the key library, and could not place an item between two siblings that other clients are moving. The key stays readable in responses.
- **One total order among siblings; a column is a view of it.** An item has one key. A column lists its items in sibling order, so dropping a card between two cards of a column means "after the first of them", and any items of other columns lying between stay out of the way.
- **Version rule:** `title`, `description`, `type` and `lead_id` need `expected_version`; `state`, moves and deletes do not. Saving an unchanged value neither raises the version nor writes an event.
- **Edits are checked twice:** the version is compared under the space lock, and the `UPDATE` itself says `WHERE version = …`, so a missed lock would still end in a 409 and never in a lost edit.
- **Lifting children on delete** puts them where the deleted item was among its siblings, in their own order. Deeper levels stay where they were.
- **`lead_id` must belong to a member of the space** is checked in the service. A composite foreign key to `memberships` would make it a database rule; it was left out because it needs `ON DELETE SET NULL (lead_id)` on a composite key, which Drizzle cannot express, and members cannot be removed in v1.
- **Tied order keys are repaired, not prevented.** The space lock makes new ties very unlikely, but old data or direct SQL could still have them, so the move gives the tied siblings after the gap fresh keys (and writes an event for each). The tests force a tie by hand.
- **Events for rewritten siblings and cascaded deletes are written one per row.** A write of one request can therefore produce several events. They share the actor and the transaction.
- **No create-space route.** v1 has none, so HTTP tests make spaces directly in the throwaway database.

## Task 6: edits to existing files (the extension proof)
No file inside `layers/core`, `workspace`, `events` or `items` was edited. Three files outside the layers were, each by one word, and each means the foundation misses a registry:
- `nuxt.config.ts`: `extends` lists layers by hand, so `./layers/tags` was added. Nuxt can also discover `layers/*` by itself; the explicit list was chosen in task 1 for visible ordering.
- `tests/server-app/nitro.config.ts`: the API-only test server lists layers by hand too (`LAYERS`).
- `tests/modules.test.ts`: the expected layer order now ends with `tags`.
- `drizzle/meta/_journal.json`: appended by drizzle-kit itself, as for any migration.
Two possible fixes for later: derive both lists from the `layers/` folder, or accept the one-line registration as the cost of an explicit order.

Design choices: `tags` reads items only through `getItem` of the items layer. Deleting a tag writes one `tag.deleted` event, not one per link (the answer lists `unlinked_item_ids`). Item delete removes links through the foreign key and writes no tag event. There is no `?tag_id=` filter on `GET /items`: that would edit the items layer, so `GET /tags/:id/items` returns the ids instead.

## Working notes

- **`events` moved below `items`:** `core ← workspace ← events ← items`. The brief had `events` above `items`, but `items` calls the event writer, and a layer may only build on layers below it. The brief now says so, and `events` also owns the writer (`recordEvent`), not `core`. `core` keeps the registry of event types.
- **One writer at a time per space.** Every write takes a transaction-level advisory lock on its space first (`lockSpace`, workspace layer). The brief asked for the lock only on parent changes. A lock on every write also keeps event ids in commit order within a space (needed for `?after=` in task 5, otherwise a slower transaction could commit an event with a smaller id after a reader had already moved past it), and rules out deadlocks. The cost is that writes in one space queue up; reads and other spaces are unaffected.
- **Unknown event types fail loudly,** like unknown actions: `recordEvent` throws if no layer registered the type.
- **`items.parent_id <> id`** is now a CHECK constraint (migration `0002`). Longer cycles are prevented by the move service under the space lock.
- **A 409 version conflict carries the stored item** in `error.current`. Added to the shared error body; it appears only on those 409s.
- **Database errors that slip past the services** are answered as 400 (bad reference, broken check) or 409 (duplicate) instead of 500. The services still check first, for clear messages.

## Working notes
- Adding a package: `docker compose exec run-102 pnpm add <package>`. If pnpm refuses with "Unexpected store location", add `--store-dir /root/.local/share/pnpm/store/v11` (the location depends on how `node_modules` was installed).
- Files written by a command in the container belong to root on the host. After `pnpm add`, run `chown` inside the container with the host user's id, or later edits on the host fail.
- Layers and Nitro plugins: file names must be unique across layers (`core.module.ts`, `items.module.ts`), because the same path in two layers means the later one overrides the first.
- The `#layers/<name>` alias is provided by Nuxt inside the app. Vitest has no Nuxt, so `vitest.config.ts` defines it.
