# run-500: SQL vs NoSQL Educational Exploration & Radial Mindmap

**Kind:** educational exploration
**Port:** 3500
**DB:** hybrid (PostgreSQL 16 Alpine + MongoDB 7)
**Question:** How does MongoDB's document model differ mechanically from PostgreSQL's relational model for hierarchical items, and how can an interactive radial mindmap, a plain list view, and on-the-fly benchmarks make these mechanics clear to a C/C++ developer?

## Scenario

A developer with a systems and C/C++ background wants to understand NoSQL and document databases from first principles. They launch the application and explore three curated educational trees—"Database Fundamentals", "Relational Mechanics (PostgreSQL)", and "Document Mechanics (MongoDB)"—built entirely from native Lerch items.

The user can view items across two distinct perspectives:
1. **Interactive Radial Mindmap:** Radiates outward from the active root with curved branches. Clicking any node centers the view or opens a detail drawer explaining the concept in C/C++ terms (comparing normalized tables and foreign keys to struct pointers, and embedded documents to inline structs/vectors). Adding a child node persists it to both databases.
2. **Plain List View:** A clean, searchable tabular list showing items, their state, tags, and parent hierarchy directly from the database. This grounds the mental model by showing the plain data before or alongside spatial graph rendering.

Switching to the **Benchmark** view, the user can generate synthetic datasets (1,000 to 10,000 items) and execute 5 comparative queries side by side. The interface reports real-time latency (ms) and displays the raw SQL query alongside the MongoDB command, clearly demystifying how relational joins and recursive CTEs compare to document aggregation pipelines.

Administrative and multi-tenant management features are intentionally omitted to keep the prototype clean, focused, and educational.

## Build

1. **Dual Storage Engines (`server/utils/db.ts`):**
   - Direct connection pool for PostgreSQL 16 via `pg`.
   - Direct client connection for MongoDB 7 via `mongodb`.
   - Schema mapping:
     - PostgreSQL: Normalized tables (`spaces`, `actors`, `items`, `tags`, `item_tags`).
     - MongoDB: Collections (`spaces`, `actors`, `items` with embedded `tags` array).

2. **Educational Seed Data (`server/seed.ts`):**
   - Three distinct hierarchical spaces/trees:
     1. `General Database Fundamentals`: Memory hierarchy, disk I/O, B-trees vs LSM-trees, ACID vs BASE.
     2. `PostgreSQL / Relational Mechanics`: Normalized tables (1NF–3NF), Foreign Keys, Joins, Write-Ahead Logging (WAL), Recursive CTEs.
     3. `MongoDB / Document Mechanics`: BSON serialization, Collections, Embedded subdocuments vs References, Document Atomicity, `$lookup` vs `$graphLookup`.
   - Strict idempotency (`ON CONFLICT DO NOTHING`, `updateOne` with `upsert: true`).

3. **Radial Mindmap View:**
   - Visual radial tree layout radiating outward from the active root or selected item.
   - Smooth SVG curved paths connecting parent and child nodes.
   - Interactive navigation: click to re-center or open the concept explanation drawer.
   - Minimal progressive item creation to add notes directly into the tree.

4. **Plain List View:**
   - Clean, searchable tabular list displaying items across spaces.
   - Displays core fields: `id`, `title`, `parent_id` (hierarchy indicator), `state`, and `tags`.
   - Allows quick filtering by space, search term, or parent.

5. **Live Benchmark & Query Inspector:**
   - Synthetic dataset generator for 1k and 10k items.
   - 5 comparative operations run in parallel or sequence against both engines:
     1. Single composite read with relations (JOINs vs single document lookup).
     2. Deep recursive subtree traversal (Recursive CTE vs `$graphLookup`).
     3. Grouped aggregation counts (`COUNT(*) GROUP BY` vs `$group` aggregation pipeline).
     4. Tag filtering and co-occurrence (junction table query vs indexed array query).
     5. Bulk batch insert (multi-row SQL transaction vs `insertMany`).
   - Side-by-side latency metrics with expandable raw query inspector (showing the exact SQL and MongoDB syntax).
