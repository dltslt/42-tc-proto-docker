# run-603: Live Collaborative Item Editing, Field Locks & Presence Cursors

**Kind:** interaction-lab  
**Port:** 3603  
**DB:** none  
**Question:** For real-time collaboration (`W7`), how should live typing in item descriptions and edit locking combine when multiple users work on the same item at once, and how are concurrent kanban moves and network disconnects visually resolved without data loss or conflicting states?

## Scenario

A developer with a systems and C/C++ background is evaluating how modern web applications manage distributed client state, race conditions, and concurrent user mutations. In desktop systems programming, concurrency is governed by explicit thread primitives, mutex locks, and deterministic memory boundaries. In a collaborative web application, multiple browser clients mutate shared documents and board states asynchronously over WebSockets (`W2`). The frontend must deliver instant, optimistic responsiveness without causing visual jitter, lost keystrokes, or clobbered updates.

The developer explores these mechanics through a synchronized split-screen workspace. Two distinct simulated actors—**Alex (User A)** in the left pane and **Bea (User B)** in the right pane—inhabit the same space in real time over a local communication channel. Both users view the same Kanban board and can simultaneously inspect or modify the same item detail drawer (e.g., *"Prepare Dinner"* or *"Refactor Navigation Shell"*).

A diagnostic control bar at the top of the interface enables developers to toggle collaborative paradigms, simulate network latency and dropouts, inspect outgoing/incoming event payloads, and evaluate two contrasting real-time editing workflows (`W7`, `§2.9 Q1`):

1. **Mode 1: Section-Level Lease Lock with Live Read-Only Preview (Pessimistic Safety):**  
   When Alex focuses or clicks "Edit Description", Alex acquires an exclusive lease lock on the description field (`item:lock`). On Bea's screen, the field transitions to a read-only state marked by a prominent amber lock badge (*"Locked by Alex — editing description"*). As Alex types, Alex's raw text or rendered markdown streams live into Bea's view in ghosted text, allowing Bea to follow the author's progress without permitting conflicting edits. The lock releases automatically upon saving, blurring, or reaching an inactivity timeout (e.g., 15 seconds without keystrokes). If Alex abandons the tab while holding the lock, Bea can activate a "Request Unlock" or "Break Lock" action to regain access.

2. **Mode 2: Simultaneous Multi-Cursor Collaborative Typing (Optimistic Fluidity):**  
   Both Alex and Bea can click into the item description simultaneously. Remote presence cursors with colored name tags (Alex in indigo, Bea in emerald) indicate caret positions and text selection ranges in real time. Remote typing indicators flash at the bottom of the editor as keystrokes occur. Text changes merge across both viewports without locking or blocking input.

3. **Concurrent Kanban Board Moves & Conflict Resolution (`W2`, `§2.9 Q1`):**  
   Both users interact with a live Kanban board (`Backlog`, `In Progress`, `Done`). When Alex begins dragging an item card, Bea's screen displays a real-time card drag indicator (a pulsating outline or ghost avatar showing *"Alex is dragging this card"*). If both users drag the same card to different columns or positions simultaneously, the system evaluates two conflict resolution strategies:
   - *In-Flight Card Locking:* Grabbing a card places a transient drag-lock on it, preventing peer users from picking it up until dropped.
   - *Optimistic Reconciliation with Collision Feedback:* Both users can drag simultaneously; upon release, the server/channel resolves the move (e.g., Last-Write-Wins) and displays a brief visual ripple and non-intrusive toast notification on the losing client (*"Item moved to 'Done' by Bea"*), smoothly animating the card to its authoritative column without visual breakage.

4. **Network Interruption, Local Draft Saving & Reconnect Recovery (`localStorage`):**  
   Each user pane includes a "Simulate Disconnect" toggle. If Alex loses network connectivity while actively editing an item description:
   - Alex's in-flight edits are debounced and saved locally to browser `localStorage`.
   - The remote client (Bea) observes the lock lease expire gracefully.
   - When Alex reconnects, the system detects a discrepancy between the remote item state and the saved local draft, presenting an inline recovery prompt (*"Found unsaved local draft from 2 minutes ago. Restore Draft | Keep Remote | View Diff"*), guaranteeing zero data loss during network hiccups.

To maintain strict focus on real-time client ergonomics, UI feedback clarity, and concurrency trade-offs, full backend database persistence (`DB=none`), user authentication (OAuth/2FA), and heavyweight server-side CRDT synchronization engines are intentionally omitted.

## What to Evaluate

### 1. Visual & Presentation Aspects
- **Lock & Availability Signaling:** Visual prominence and clarity of the field lock badge (*"Locked by Alex"*), disabled overlays, and lock ownership indicators versus standard editable inputs.
- **Live Streamed Preview:** Aesthetic quality of ghosted/streaming text updates in Mode 1—whether watching a peer type in read-only mode feels smooth and informative or visually distracting.
- **Presence Cursors & Typing Awareness:** Readability and smoothness of colored remote cursors, selection highlights, and floating user name tags in Mode 2 without obscuring active text.
- **Board Drag & Collision Feedback:** Visual clarity of remote card dragging (pulse halos, ghost shadows) and animation smoothness when a card is moved across columns by a peer.
- **Draft Recovery & Disconnect UI:** Presentation of offline warning banners and the unsaved draft comparison/restore interface.

### 2. Procedural & Workflow Aspects
- **Friction vs. Freedom:** Whether the rigid safety of lease locks (Mode 1) provides greater user confidence during a team demo, or whether free-form concurrent editing (Mode 2) feels essential for collaborative note-taking.
- **Lock Hoarding & Inactivity Recovery:** How gracefully the system recovers when a user walks away with an active lock, evaluating the user experience of auto-release timers and explicit "Break Lock" overrides.
- **Keystroke Latency & Cursor Stability:** Ensuring that remote updates arriving over the channel do not steal focus, cause cursor jumping, or introduce typing lag for the local user.
- **Concurrent Drag-and-Drop Ergonomics:** The psychological feel of having a Kanban card moved or re-ordered by another user while actively viewing or interacting with the board.
- **Offline Resilience:** The workflow efficiency of recovering an uncommitted draft after an unexpected connection drop or page refresh.

### 3. Technology & Stack Choices
- **Nitro / WebSockets vs. BroadcastChannel (`W2`):** Ergonomics and developer experience of managing live duplex events (`item:lock`, `item:typing`, `item:update`, `kanban:move`) across simulated browser clients in Nuxt.
- **Vue 3 Reactivity & Focus Preservation:** How Vue's reactive state tracking (`ref`, `reactive`, `watch`) handles incoming remote text patches without resetting DOM selection ranges or triggering re-render loops.
- **State Arbitration Strategies:** Technical trade-offs between pessimistic lease locking with time-based heartbeats versus optimistic updates with Last-Write-Wins (LWW) resolution.
- **Client Storage Architecture:** Structuring `localStorage` keys (`draft:item:<id>:<actor>`), debouncing frequency, and lifecycle cleanup upon successful remote synchronization.

## Done When

- [ ] Split-screen workspace renders two distinct simulated personas (User A "Alex" and User B "Bea") side-by-side with synchronized real-time cross-client communication.
- [ ] Diagnostic control bar allows toggling between **Field Lock with Live Preview** (Mode 1) and **Simultaneous Multi-Cursor Editing** (Mode 2) at runtime.
- [ ] In Mode 1: Focusing or clicking "Edit" in User A's description field locks the field for User B with a visible lock badge, streams User A's typing in real time as a read-only preview for User B, and releases the lock upon save, blur, or inactivity.
- [ ] In Mode 1: When User A holds a lock and becomes inactive, the system demonstrates both automatic lease expiration and an interactive "Break Lock" action for User B.
- [ ] In Mode 2: Both users can type concurrently in the description field, displaying live remote cursors, text selection highlights, and typing indicators without caret jumping or focus loss.
- [ ] Dragging an item card across Kanban columns updates the peer's board in real time with a visual drag indicator/glow, and simultaneous moves resolve deterministically with clear collision feedback.
- [ ] Toggling "Simulate Disconnect" for a user stops socket transmissions; active edits persist to `localStorage`; upon reconnecting, an interactive draft recovery banner prompts the user to restore or discard local changes.
