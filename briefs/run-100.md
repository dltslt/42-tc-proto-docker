# Brief: run-100 — Baseline task tool, built to grow

## Scenario

A small team wants a task tool that stays out of the way. Build the **baseline only**
(spaces & actors, items with recursive hierarchy, progressive creation, state & kanban)
as a vertical slice: UI → Nitro API → PostgreSQL. The question this run answers:

> Can the four baseline mechanics sit on a structure that later grows into a
> production tool (tags, blockers, events, real auth, permissions) without a rewrite?

## What to build

- **Database:** `DB=postgres`. Plain `pg` queries, all SQL inside `server/utils/`.
- **Spaces & actors:** one `personal` and one `organization` space, several seeded actors
  (humans and one agent). A "current user" selector in the header switches persona
  (no real auth). A space switcher shows the spaces the persona belongs to.
- **Items & hierarchy:** one `items` table with `parent_id` (project > epic > story > task > subtask).
- **Progressive creation:** a single title input creates an item; everything else is edited later.
- **State & kanban:** board with columns `backlog`, `in progress`, `done`; moving a card
  updates its column (and `state` through a small mapping). Native HTML5 drag-and-drop.
- **Tree view:** a nested list of the hierarchy, with the same create/edit actions.
- **Product stubs** as separate server modules: `can(actor, action, resource)` (allow all),
  ordering policy, default column placement (first `unstarted` column).
- **Validation:** `zod` on every API input.
- **UI:** Nuxt UI + Tailwind CSS.
- **Seed:** idempotent `server/seed.ts` with a small realistic project (epics, tasks, subtasks)
  across both spaces.

## Out of scope

Tags, blockers, artifacts, events log, scoring, scheduling, real auth, real-time sync.

## Done when

1. `make seed RUN=100` succeeds and can be run repeatedly without errors or duplicates.
2. `http://localhost:3100` shows a header with a current-user selector and a space switcher;
   switching either changes what is shown.
3. Typing a title and pressing Enter creates an item that appears immediately (board and tree).
4. Creating an item under a parent (child/subtask) shows it nested in the tree view.
5. Dragging a card to another column persists after page reload, and `state` follows the column.
6. An item's title, description and state can be edited and the change persists.
7. Invalid API input returns a 4xx with a readable message (not a 500).
8. Items of one space are never visible in another space.
