# run-608: Inline Link Auto-Capture, File Upload Dropzone & Bidirectional Artifact Chain

**Kind:** interaction-lab  
**Port:** 3608  
**DB:** none  
**Question:** When capturing external resources in items, does silent auto-creation or a proactive 1-click confirmation pill provide the best balance of speed and artifact hygiene (§2.5 Q1, Q2), how does a client-side drag-and-drop dropzone with preview modals satisfy Module W12, and how should bidirectional navigation between items and shared artifacts behave across an item hierarchy?

## Scenario

A developer or team lead is managing complex work across a multi-level item hierarchy (Space $\to$ Project $\to$ Epic $\to$ Task $\to$ Subtask). In their day-to-day workflow, work items accumulate external references: pull requests, Figma boards, RFC documents, design assets, and architecture diagrams. 

Under the Lerch philosophy, an ordinary change takes the fewest steps: typing a link collects it, and the system stays out of the way. However, two interaction models compete for how links are captured, and file attachments must provide robust validation and previews without turning the interface into a bloated attachment manager:

1. **Inline Link Auto-Capture vs. Confirmation Pill (`§2.5 Q1`):**
   - *Mode A (Silent Auto-Capture):* As the user types or pastes a URL in an item's title, description, or quick-input field, the system automatically detects the URL, derives a clean title (from the domain and URL path), and registers an attached `kind: "link"` artifact in the item's artifact tray without interrupting the user.
   - *Mode B (Proactive 1-Click Pill):* As the user types or pastes a URL, a sleek, non-intrusive floating chip (*"Create Artifact?"* or `[+ Link: github.com]`) surfaces near the cursor. Pressing `Tab` or clicking the chip promotes the URL into a tracked artifact; ignoring it leaves the URL as plain text.

2. **Existing Artifact Suggestion & Deduplication (`§2.5 Q2`):**
   - When the user enters a URL or title that matches an artifact already registered in the space (e.g. an existing PR link or shared design specification), the interface proactively surfaces an existing artifact badge (*"Link existing artifact 'RFC-42 Specification' (referenced by 2 other items)"*) rather than creating a duplicate artifact record.

3. **Drag-and-Drop File Upload Dropzone & Previews (`Module W12`):**
   - The item detail drawer features an integrated drag-and-drop file zone (and click-to-browse file input).
   - The dropzone enforces client-side MIME type verification (images: PNG, JPEG, SVG; documents: PDF; text: Markdown, TXT) and file size constraints (e.g. 10 MB maximum). Dropping an unsupported file format or an oversized payload displays high-contrast inline validation feedback explaining the rejection.
   - Valid uploads simulate realistic network latency and bandwidth with an animated progress bar (`0%` $\to$ `100%`) and an immediate "Cancel" action.
   - Uploaded files (`kind: "file"`) offer rich inline preview modals:
     - Images: Lightbox modal with zoom, resolution, and byte-size metadata.
     - PDFs: Embedded viewer pane with document navigation.
     - Markdown / Text: Formatted HTML rendering with a toggle to inspect raw source.
   - File deletion provides a 5-second undo toast before permanent removal.

4. **Bidirectional Artifact Chain & Hierarchical Explorer:**
   - *Forward Lookup (Item $\to$ Artifacts):* An item displays its directly attached artifacts. A toggle enables viewing the *Hierarchical Artifact Chain*, which rolls up artifacts attached to ancestor items (e.g. a Project-level specification or Epic-level mockup) with distinct visual ancestry breadcrumbs.
   - *Reverse Lookup (Artifact $\to$ Items / Backlink Inspector):* Clicking any artifact opens an Artifact Inspector displaying its metadata, preview, and an exhaustive list of all items across the workspace that reference it. Clicking any connected item immediately re-centers or navigates to that item.
   - *Multi-Item Re-linking:* Allows attaching an existing workspace artifact to the active item with one click, establishing a many-to-many relationship without duplicating file storage.

Backend disk persistence, cloud S3 storage, full-text OCR extraction, and multi-user collaborative write locks are intentionally omitted to keep this prototype strictly focused on client-side interaction ergonomics, validation UX, and bidirectional graph navigation.

## What to Evaluate

### 1. Visual / Presentation Aspects
- **Capture Friction & Noise:** Does silent auto-creation create visual clutter when casual or temporary markdown links are pasted, or does the floating 1-click confirmation pill feel distracting during continuous writing?
- **Dropzone Ergonomics:** Visual clarity of drag-over states (`dragenter`, `dragleave`), file drop targets, upload progress bars, and inline error banners when files fail validation.
- **Preview Modal Fidelity:** Presentation quality and responsiveness of client-side preview modals (image lightboxes, embedded PDF viewers, and formatted markdown cards) versus generic browser downloads.
- **Hierarchy Distinction:** Visual differentiation between directly attached artifacts and ancestor-inherited artifacts (e.g. subtle styling, inheritance badges, and parent breadcrumbs).

### 2. Procedural / Workflow Aspects
- **Keystroke Efficiency:** The number of keystrokes and clicks required to attach a link or file while authoring an item. Does pressing `Tab` to accept a link pill preserve typing flow?
- **Deduplication Experience:** How effectively existing artifact suggestions prevent redundant duplicate artifacts when multiple team members paste the same URL across different tasks.
- **Upload Error Handling & Recovery:** The experience of dropping mixed batches (e.g. one valid image and one oversized file) and canceling in-flight uploads.
- **Cross-Item Navigation:** How quickly a developer can trace from a shared design artifact back to all related tasks, or discover overarching project documents from a leaf subtask.

### 3. Technology / Stack Choices (Libraries, DX & Ergonomics)
- **Client-Side File & Memory Management:** Evaluating browser `File` and `Blob` APIs, `URL.createObjectURL()`, and explicit memory cleanup (`URL.revokeObjectURL()`) inside Vue lifecycle hooks to prevent memory leaks (analogous to `free()` in C/C++).
- **URL Extraction & Parsing:** Comparing regex-based link detection against native JavaScript `URL` constructor parsing for robust link extraction and domain title derivation.
- **Client Validation Primitives:** Assessing native browser MIME type inspection (`file.type`) and byte size checks (`file.size`) without relying on heavy external validation libraries.
- **Zero-Backend Preview Techniques:** Evaluating native `<iframe>` / `<object>` tags for PDFs and lightweight client markdown parsers for document previews.
- **Bidirectional Reactive State:** Managing many-to-many relationships between items and artifacts in a reactive Vue store without backend database round-trips.
