# run-606: Personal Welcome Analytics Dashboard & Interactive Chart-to-PDF Pipeline

**Kind:** slice  
**Port:** 3606  
**DB:** none  
**Question:** How does the post-login personal welcome dashboard aggregate and cross-filter items across spaces, which charting technology (lightweight reactive SVG vs. external canvas/library) provides the best DX and bundle efficiency, and can client-side PDF generation cleanly satisfy multi-chart snapshot exports without server-side headless browsers?

## Scenario

A user signs into Lerch and lands immediately on their **Personal Welcome Analytics Dashboard** (**DA1**). Instead of dropping the user into an arbitrary project board or an empty page, this welcome view serves as a quiet personal cockpit, aggregating open tasks, blockers, and recent achievements across all spaces the user belongs to (both their `personal` space and shared `organization` spaces).

The developer or reviewer explores the dashboard through three interconnected surfaces:

1. **The Four Interactive Analytics Charts:**
   - **Weekly Velocity (Line Chart):** Items finished per week over a rolling window (defaulting to the last 8 weeks), computed directly from `events` transition logs where state moved to `done`.
   - **Column Distribution (Bar Chart):** Open items categorized across active `kanban` columns (`backlog`, `unstarted`, `in progress`, `review/qa`).
   - **Space Allocation (Pie/Donut Chart):** Distribution of the user's items across their personal workspace and organizational team spaces.
   - **Blocker Impact (Bar Chart):** Open items grouped by the 4-step blocker severity invariant (`cannot do anything`, `will be stuck`, `slowed down`, `nice to have`), alongside unblocked items.

2. **Bidirectional Cross-Filtering & Drill-Down:**
   - Every chart element is an interactive filter. Clicking a slice in the Space pie chart, a column in the Kanban bar chart, or a severity tier in the Blocker chart immediately cross-filters the rest of the dashboard.
   - A persistent filter bar displays active filter chips with one-click removal and a "Clear All" action.
   - A responsive **Drill-Down Summary Table** sits below the charts, displaying the filtered set of underlying items (title, space badge, kanban column, blocker severity, effort, and contributors), confirming that the charts remain grounded in real items.
   - Global controls allow switching date ranges (`Last 7 days`, `Last 30 days`, `Last 8 weeks`, `Custom`) and filtering by space.

3. **Live Event Stream Simulation (W2):**
   - An in-browser diagnostic simulator bar allows firing synthetic WebSocket events: completing a task, moving a task to another kanban column, logging a new blocker with high severity, or creating a new item.
   - The dashboard animates updates reactively in real time, demonstrating how incoming `W2` WebSocket events shift chart geometry without jarring full-page refreshes.

4. **Comparative Charting Tech & PDF Export Pipeline:**
   - **Tech Comparison Toggle:** The developer toggles between two implementation paradigms:
     - *Handcrafted Reactive SVG:* Built with native Vue template primitives (`<svg>`, `<path>`, `<rect>`), zero third-party dependencies, and CSS transitions.
     - *Canvas/Library Implementation:* Built with an industry-standard charting library (e.g., Chart.js or Unovis), relying on canvas rendering.
     A diagnostic overlay displays real-time bundle size overhead, DOM node counts vs. canvas memory, and render latency (ms).
   - **Dual PDF Snapshot Pipeline:** The developer evaluates two client-side approaches for the PDF export requirement (§2.6 Q6):
     - *Approach A (CSS Print Stylesheet):* Invokes native `window.print()` using an optimized `@media print` stylesheet that strips navigation, hides simulation controls, snaps charts into a print-friendly 2x2 grid, and prevents page breaks inside charts.
     - *Approach B (Client-Side Vector/Canvas PDF):* Generates and downloads a standalone `.pdf` document directly in the browser (e.g., via `html2canvas` + `jspdf` or SVG vector serialization), comparing visual fidelity, download ergonomics, and font consistency.
   - **CSV Export:** Includes a one-click button that exports the currently aggregated and filtered chart dataset into a clean `.csv` file.

To keep the prototype scoped and focused, persistent relational/document database engines, complex user authentication/password reset flows, granular role-based permission matrices, and interactive kanban drag-and-drop boards are intentionally omitted. All data is backed by realistic, deterministic in-memory fixtures.

## What to Evaluate

### 1. Visual / Presentation Aspects
- **Spatial Layout & Hierarchy:** Visual balance of the 4-chart layout on standard desktop screens (1080p/1440p) down to responsive laptop viewports; whether the 2x2 grid or a stacked layout presents metrics most clearly.
- **Micro-Interactions & Hover Feedback:** Rich tooltips on hover revealing exact values, percentages, and trend indicators; visual cues distinguishing clickable chart segments (e.g., cursor pointer, hover glow, slice offset, bar dimming for unselected items).
- **Active Filter State:** Clarity of the sticky filter chip bar, active selection styling on chart segments, and graceful empty/zero-data state presentations when cross-filters yield no results.
- **PDF Snapshot Fidelity:** Visual comparison of the exported PDF between CSS `@media print` output and client-side canvas generation: font rendering, legend placement, chart resolution, margin hygiene, and avoidance of awkward page splits.

### 2. Procedural / Workflow Aspects
- **Welcome Cockpit Ergonomics:** Does landing on this dashboard give a developer or team member an instantaneous, actionable grasp of their workload, blockers, and recent momentum before diving into individual tasks?
- **Interactive Drill-Down Workflow:** Keystroke and click efficiency of drilling down into problem areas (e.g., "Show me the critical blockers in the Web Team space") through direct chart interaction versus traditional multi-dropdown form filtering.
- **Live WebSocket Event Perception:** How live item updates feel to the user: do smooth SVG/canvas transitions communicate incoming changes effectively, or do live metric shifts distract from current analysis?
- **Export Friction:** Usability and speed of generating executive PDF summaries or raw CSV data exports for external team status updates.

### 3. Technology / Stack Choices
- **Handcrafted Reactive SVG vs. External Charting Library:**
  - *Developer Experience (DX):* Compare building charts using declarative Vue `<template>` loops (`v-for`, reactive SVG coordinates, CSS transitions) against configuring an imperative canvas library (e.g., Chart.js or Unovis).
  - *Bundle & Performance Impact:* Contrast zero-dependency SVG (0 kB external footprint, native DOM inspection) against library bundle weight (60–150+ kB), comparing memory usage and render latency during rapid event simulation.
  - *C/C++ Systems Perspective:* Analogizing SVG to a retained-mode scene graph maintained by the browser versus Canvas as an immediate-mode pixel buffer, weighing DOM overhead against pixel manipulation flexibility.
- **Client-Side PDF Generation vs. Server-Side Headless Browsers:**
  - Evaluate whether pure client-side PDF export (CSS `@media print` or browser-side canvas-to-PDF) satisfies 42 evaluation defense requirements cleanly without the operational burden of a headless Chromium container (e.g., Puppeteer) in Docker.
  - Assess cross-browser consistency and print-dialog friction across modern browsers.
- **Client-Side Time-Series Aggregation:**
  - Assess reactive data aggregation performance in TypeScript (grouping raw `events` into rolling ISO calendar weeks, calculating column counts, and filtering multi-dimensional items) entirely in the browser without database query overhead.
