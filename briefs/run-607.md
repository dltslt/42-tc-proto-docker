# run-607: Advanced Search, Multi-Select Bulk Operations & Import Error Triage Lab

**Kind:** interaction-lab  
**Port:** 3607  
**DB:** none  
**Question:** How do multi-faceted search filters, sorting, and pagination integrate with multi-item bulk mutations in a dense list view, and does an interactive pre-commit validation wizard resolve the data import error dilemma compared to all-or-nothing or unassisted partial imports?

## Scenario

A team member or project lead needs to locate, organize, and update large batches of work across multiple spaces. Rather than drilling down space-by-space through kanban boards, they navigate to the central list view to filter items across personal and organization spaces, perform bulk updates, export filtered subsets, and import external task lists via CSV or JSON.

The user explores three interconnected interaction areas:

1. **Faceted Search, Sorting & Pagination (**W11**):**
   The user applies combined filters across multiple dimensions:
   - **Scope:** Filter by space (Personal vs. Organization spaces).
   - **Lifecycle & Placement:** Filter by `state` (`unstarted`, `started`, `done`, `discarded`) and `kanban` column (`backlog`, `in_progress`, `review`, `done`).
   - **Attributes:** Multi-select filtering by `tags` (e.g., `#frontend`, `#backend`, `#bug`), assigned `contributor` / actor, and date ranges (created or scheduled dates).
   - **Text Query:** Instant debounced full-text search across titles and descriptions.
   - **Sorting & Paging:** Sorting by `title`, `created_at`, `scheduled_time`, or `effort` (ascending and descending). Results render in a clean 20-item paged table with navigation controls.
   - **URL Synchronization:** Active filters, sort keys, and page numbers sync directly to URL query parameters (`?q=...&tags=...&page=...`), allowing filtered views to be bookmarked, reloaded, or shared.
   - **Dataset Scale Switcher:** A control toggle switches between a realistic baseline workspace (~200 items) and a synthetic high-volume dataset (1,000 to 10,000 items) to observe client-side query and pagination responsiveness.

2. **Multi-Select List View & Floating Bulk Action Dock (**DA2**):**
   When reviewing items in the tabular list, the user selects items using row checkboxes, range selection (`Shift + Click`), "Select all on page", or "Select all N items matching current filter".
   
   Selecting one or more items summons a floating contextual action dock anchored at the bottom of the screen. From this dock, the user executes batch mutations in a single action:
   - **Batch Column Move:** Move all selected items to a different kanban column.
   - **Batch State Transition:** Advance or discard selected items across lifecycle states.
   - **Batch Tagging:** Append or remove tags across all selected items.
   - **Batch Deletion:** Delete selected items with a confirmation prompt showing item count.
   - **Batch Export:** Export selected items directly to CSV or JSON.
   
   Mutations update reactive state immediately, surfacing a temporary toast notification with an "Undo" option for non-destructive reversal of accidental batch operations.

3. **CSV/JSON Import Wizard & Error Triage Comparison (§2.7 Q2, **DA2**):**
   The user opens an import modal to ingest external items into a space via CSV or JSON. The lab provides three bundled sample files for testing:
   - `clean_tasks.csv`: Fully valid tasks adhering to domain invariants.
   - `messy_tasks.csv`: Realistic data with validation errors (missing titles, invalid state values like `"pending"`, unmapped kanban columns, negative effort durations).
   - `malformed_tasks.json`: Syntactically invalid or structurally broken payload.

   Instead of submitting blindly and discovering failures post-upload, the interface parses and validates rows client-side before commit, presenting an **Interactive Pre-Commit Validation Table**. Rows are categorized into Valid (green badges) and Invalid (red cell highlights with specific row numbers and error tooltips).

   The user can switch between and evaluate three distinct error-handling strategies:
   - **Strategy A: Strict All-or-Nothing (Atomic Rejection):** If any row fails validation, the entire import is blocked until the external file is corrected.
   - **Strategy B: Unassisted Partial Import:** Valid rows import immediately, while invalid rows are discarded or dumped into a downloadable error CSV.
   - **Strategy C: Interactive Triage Wizard ("Preview, Inline-Fix & Selective Import"):** The user can double-click invalid cells directly in the preview table to correct errors (e.g., replace `"pending"` with `"unstarted"`, add a missing title), toggle "Skip invalid rows" to import only valid items, or proceed once all errors are resolved.

Full database engine persistence (`DB=none`), multi-tenant administrative settings, OAuth/2FA credential management, and multi-user WebSocket conflict resolution are intentionally omitted to keep the prototype strictly focused on search ergonomics, reactive bulk list operations, and client-side data import validation workflows.

## What to Evaluate

### 1. Visual / Presentation Aspects
- **Faceted Filter Bar Density & Layout:** Evaluating compact inline filter chips versus an expandable filter drawer; clarity of active filter badges and the 1-click "Clear all filters" affordance.
- **Floating Bulk Action Dock:** Elevation, entrance/exit transitions, and visual prominence of the floating dock without obscuring row contents or pagination controls.
- **Pre-Commit Validation Diagnostics:** Visual clarity of error indicators in the import preview table (colored row borders, red cell highlights, hover tooltips with explicit validation failure messages, and valid-vs-invalid summary cards).
- **Pagination & Sorting Ergonomics:** Visual state of sortable column headers (direction arrows, active sort indicators), pagination buttons, and informative summary text ("Showing 21–40 of 184 items").

### 2. Procedural / Workflow Aspects
- **Search Composition Speed:** Keystroke and click counts required to combine multiple filters (e.g., finding all `#backend` items in `Engineering Org` currently `in_progress` and sorted by `effort`).
- **Bulk Action Keystroke & Mouse Efficiency:** Ergonomics of `Shift + Click` range selection, multi-page selection boundaries ("Select this page" vs. "Select all 240 filtered items"), and the safety feedback of bulk mutation toasts with undo capability.
- **Import Error Recovery Journey (§2.7 Q2):** Comparing the friction and cognitive load across Strategy A (rejection requiring external file editing), Strategy B (partial import with potential untracked dropped data), and Strategy C (in-app preview correction and selective skip).
- **URL Query State Round-Tripping:** Verifying whether deep-linked URLs preserve complete search, filter, sort, and pagination state across browser reloads or tab duplication.

### 3. Technology / Stack Choices
- **Client-Side Reactive Filtering & Sorting:** Evaluating Vue 3 `computed` pipelines versus in-memory indexing libraries for multi-facet filtering over 200 vs. 10,000 items, measuring filter latency and frame drops.
- **In-Browser File Parsing & Validation:** Assessing client-side parsing libraries (e.g., PapaParse for CSV, native `JSON.parse` with schema validation) for speed, bundle footprint, and quality of line-by-line error messages.
- **Nuxt Router Query Synchronization:** Ergonomics of two-way binding search state to `useRoute().query` and `useRouter().push()` without triggering redundant page re-renders or unwanted browser history bloat.
- **Table Virtualization vs. Paged DOM:** Evaluating whether fixed 20-item pagination eliminates the need for complex DOM virtualization while maintaining 60 FPS interactions.
